## ۱) نتیجهٔ بررسی ریپوها

### A. CluvexStudio/Aether  ⭐1.6k — **هستهٔ اصلی پروژه**

| مورد | یافته |
|---|---|
| زبان | Rust (نسخه 1.5.0، ۲۹ ژوئیهٔ ۲۰۲۶ — یعنی دیروز آپدیت شده، پروژهٔ زنده) |
| لایسنس | **AGPL-3.0** (مهم — بخش ۴) |
| خروجی | باینری CLI که یک **SOCKS5 محلی روی 127.0.0.1:1819** بالا می‌آورد |
| پروتکل‌ها | MASQUE روی HTTP/3(QUIC) و HTTP/2(TLS)، WireGuard، Nested-WG (`gool`) |
| ضدDPI | فرگمنت‌کردن TLS ClientHello، `aethernoize`، اثرانگشت‌های TLS متفاوت (`split-tls12` / `plain-tls13` / `chrome`) |
| کشف اندپوینت | `prober.rs` + `wg_prober.rs` + **اعتبارسنجی data-plane** (فقط وقتی gateway قبول می‌شود که واقعاً ترافیک رد کند، نه صرفاً هندشیک) |
| اندروید | **از قبل build اندروید دارد** — `.github/workflows/release.yml` با `cargo-ndk` برای `arm64-v8a`، `armeabi-v7a`، `x86_64` باینری Termux می‌سازد |
| کنترل | همه‌چیز با **متغیر محیطی** قابل تنظیم است: `AETHER_PROTOCOL`, `AETHER_SCAN`, `AETHER_NOIZE`, `AETHER_SOCKS`, `AETHER_DNS`, `AETHER_MASQUE_H2_FRAGMENT`, `AETHER_QUICK_RECONNECT`, … |

**چرا این خبر خیلی خوبیه:** چون Aether کاملاً با env var کنترل می‌شود و SOCKS5 می‌دهد، برای ساخت اپ نیازی به fork کردن یا دست‌کاری کد Rust نیست. اپ اندروید باینری را اجرا می‌کند و از طریق env var و لاگ stdout با آن حرف می‌زند. این یعنی **هر آپدیت آیندهٔ Aether بدون بازنویسی اپ قابل استفاده است.**

**دو هشدار امنیتی که خودِ مستندات ریپو داده و باید در اپ حل شود:**
1. SOCKS5 آن **هیچ احرازهویتی ندارد**. در اندروید باید حتماً روی `127.0.0.1` بایند شود و علاوه بر آن با UID-filtering محافظت شود، وگرنه هر اپ دیگری روی همان گوشی می‌تواند از تونل شما استفاده کند.
2. هویت WARP باید بین اجراها **ذخیره** شود (`/data`)، وگرنه هر بار دستگاه جدید ثبت می‌شود و Cloudflare محدودتان می‌کند.

### B. patterniha/SNI-Spoofing  ⭐2.6k — **ایده، نه کد قابل استفاده**

| مورد | یافته |
|---|---|
| زبان | Python (۵۵۶ خط) |
| لایسنس | GPL-3.0 |
| وابستگی | `pydivert` → **WinDivert** |
| یعنی | **فقط ویندوز است.** روی اندروید اصلاً اجرا نمی‌شود |
| جایگزین عملی | `hufrea/byedpi` — همان تکنیک، زبان C، لایسنس MIT، بدون نیاز به روت |

**کاری که می‌کند:** یک TCP معمولی به IP مقصد باز می‌کند، و هم‌زمان با درایور کرنل یک بستهٔ **ClientHello جعلی با SNI جعلی** (`auth.vercel.com`) و **شمارهٔ ترتیب اشتباه** (`BYPASS_METHOD = "wrong_seq"`) تزریق می‌کند. DPI آن بستهٔ جعلی را می‌بیند و کانکشن را «مجاز» طبقه‌بندی می‌کند، ولی سرور واقعی چون seq غلط است آن را دور می‌ریزد.

**کد قابل پورت نیست، ولی ایده کاملاً قابل بازسازی است — و بدون روت:**

کد پایتون به‌خاطر `pydivert`/WinDivert فقط ویندوزی است. تزریق مستقیم بستهٔ خام هم روی اندروید نیاز به `CAP_NET_RAW` دارد که به اپ‌های عادی داده نمی‌شود. **اما** بررسی سورس ByeDPI (`hufrea/byedpi`، لایسنس **MIT**) نشان داد همان اثر با یک ترفند userspace بدون هیچ امتیاز ویژه‌ای به دست می‌آید:

**مکانیزم بدون‌روتِ ByeDPI (فایل `desync.c`):**
1. `setsockopt(IP_TTL, low)` روی یک سوکت TCP کاملاً معمولی
2. `vmsplice(..., SPLICE_F_GIFT)` → صفحات حافظهٔ حاوی **ClientHello جعلی** به کرنل واگذار می‌شود
3. `splice()` آن را روی سوکت می‌فرستد — TTL پایین باعث می‌شود بسته به DPI برسد ولی قبل از سرور بمیرد
4. `restore_state()` **همان صفحهٔ حافظه را در جا با دادهٔ واقعی `memcpy` می‌کند**
5. کرنل هنگام retransmit، دادهٔ واقعی را **با همان sequence number** می‌فرستد

نتیجه دقیقاً معادل `BYPASS_METHOD="wrong_seq"` ریپوی patterniha است: DPI یک ClientHello با SNI جعلی می‌بیند و کانکشن را مجاز می‌شمارد، سرور واقعی هرگز آن را نمی‌بیند. **صفر نیاز به روت.**
لایهٔ کمکی: `TCP_MD5SIG` با کلید بی‌اعتبار → سرور بستهٔ جعلی را دور می‌ریزد، DPI اهمیتی نمی‌دهد.
پارامتر `--fake-sni` هم معادل مستقیم `FAKE_SNI: "auth.vercel.com"` در `config.json` است.

| تکنیک | بدون روت؟ | وضعیت |
|---|---|---|
| Fake ClientHello با SNI جعلی + TTL پایین | ✅ | موتور ByeDPI |
| هم‌ترازی seq جعلی و واقعی (اثر `wrong_seq`) | ✅ | ترفند vmsplice + memcpy |
| TCP_MD5SIG برای دورانداختن در سمت سرور | ✅ | موتور ByeDPI |
| Split / Disorder / OOB urgent-byte | ✅ | موتور ByeDPI |
| فرگمنت ClientHello در تونل | ✅ | Aether: `--fragment` |
| کنترل بایت‌به‌بایت هدر IP/TCP (checksum غلط، seq دلخواه) | ❌ | تنها چیزی که از دست می‌رود؛ فقط با روت |

**نقش نهایی در پروژه:** موتور desync به‌صورت کتابخانهٔ native (`libbyedpi.so`، زیر ۲۰۰KB) داخل اپ قرار می‌گیرد و سه حالت کاری می‌سازد:

- **Direct** — فقط desync، بدون سرور واسط. IP عوض نمی‌شود، سریع‌ترین حالت. برای وقتی اینترنت سالم است و فقط مقصد فیلتر شده.
- **Tunnel** — فقط Aether، تونل رمزنگاری‌شده، IP عوض می‌شود.
- **Combined** — desync جلوی Aether، برای وقتی حتی دسترسی به لبهٔ Cloudflare هم مسدود است. سناریویی که هیچ‌کدام به‌تنهایی حل نمی‌کنند.

انتخاب بین این سه، یکی از تصمیم‌های اصلی AI Router خواهد بود.

## ۲) معماری اپ

```
┌──────────────────────────────────────────────────────────┐
│  UI (Kotlin + Jetpack Compose + Material 3)              │
│  دکمهٔ تک‌کلیکی · منوی همبرگری → تنظیمات پیشرفته / کنسول  │
└────────────┬─────────────────────────────────────────────┘
             │
┌────────────▼─────────────────────────────────────────────┐
│  AetherVpnService  (android.net.VpnService)              │
│   ├─ tun2socks (hev-socks5-tunnel)  tun ⇄ SOCKS5         │
│   ├─ AetherProcess: اجرای libaether.so از jniLibs        │
│   │     env: AETHER_PROTOCOL/SCAN/NOIZE/SOCKS/DNS …      │
│   ├─ DesyncProxy (اختیاری، لایهٔ SNI-Spoofing بدون روت)   │
│   ├─ ConnectionVerifier  ← «واقعاً وصل شدی؟»              │
│   └─ LogBus  ← استریم لاگ زنده به کنسول تشخیصی           │
└────────────┬─────────────────────────────────────────────┘
             │
┌────────────▼─────────────────────────────────────────────┐
│  AI Router (محلی، آفلاین)                                 │
│  یادگیری کدام profile/endpoint روی اپراتور و ساعت شما     │
│  جواب می‌دهد → انتخاب خودکار در کلیک بعدی                 │
└──────────────────────────────────────────────────────────┘
```

باینری Aether به‌صورت `libaether.so` داخل `jniLibs/<abi>/` قرار می‌گیرد (با `extractNativeLibs=true`) — این تنها روش مجاز و پایدار برای اجرای باینری بومی در اندروید ۱۰+ است، چون مسیر `nativeLibraryDir` تنها جایی است که هنوز اجازهٔ exec دارد.

## ۳) چهار خواستهٔ اصلی شما — چطور پیاده می‌شود

### ① اتصال تک‌کلیکی
یک دکمه. پشت صحنه: انتخاب profile توسط AI Router → بالا آوردن VpnService → اجرای Aether با env مناسب → پارس لاگ تا لحظهٔ آماده شدن SOCKS → **اجرای تست اتصال** → فقط آن موقع دکمه سبز می‌شود. اگر تست رد شود، خودکار profile بعدی امتحان می‌شود (تا N بار) بدون اینکه کاربر کاری کند.

### ② تست واقعی اتصال (نه «سبز شدن آیکون»)
شش تست، همه از **داخل** تونل:

1. **IP خروجی قبل/بعد** — اگر عوض نشده باشد ⇒ شکست
2. **`cdn-cgi/trace`** — بررسی `warp=on` و کشور
3. **DNS leak** — رزولوشن باید از رزولور تونل بیاید نه DNS اپراتور
4. **IPv6 leak** — چک نشت v6 وقتی تونل v4 است
5. **تست throughput واقعی** — دانلود چند صد کیلوبایت، اندازه‌گیری سرعت و پایداری
6. **UDP/QUIC reachability** — تا معلوم شود فقط TCP رد نمی‌شود

نتیجه به‌صورت کارت «گزارش سلامت اتصال» با ✅/⚠️/❌ نمایش داده می‌شود و کامل در لاگ می‌رود.

### ③ کنسول تشخیصی امن (شبیه Termux) — منوی همبرگری، کنار تنظیمات پیشرفته
- لاگ زندهٔ رنگی هستهٔ Aether + tun2socks + سرویس VPN، با فیلتر سطح، جستجو، خروجی گرفتن و **حذف خودکار داده‌های حساس** (کلید WireGuard، توکن Zero-Trust، IP کاربر) قبل از اشتراک‌گذاری
- ورودی دستور با مجموعهٔ محدود و whitelist شده:
  `ping`, `dns <host>`, `trace <host>`, `curl-test <url>`, `ip`, `route`, `stats`, `config show`, `leak-test`, `bench`, `profile list/try`, `core restart`, `logcat`, `export`
- **بدون shell واقعی، بدون `sh -c`، بدون دسترسی به فایل‌سیستم سیستم.** هر دستور یک تابع Kotlin است، نه رشته‌ای که به مفسر داده شود. این تفاوت بین «ابزار تشخیص» و «در پشتی» است.

### ④ آپدیت داخل برنامه — با محافظ چندلایه
نگرانی شما کاملاً بجاست؛ این خطرناک‌ترین بخش هر اپ است. طراحی:

1. فقط از **GitHub Releases API روی ریپوی سفت‌شدهٔ خودمان** (owner/repo در کد ثابت، غیرقابل تغییر از تنظیمات)
2. **certificate pinning** روی اتصال به GitHub
3. تأیید **SHA-256** فایل در برابر مقدار منتشرشده
4. تأیید **امضای دیجیتال APK دانلودشده** و مقایسه با گواهی نسخهٔ نصب‌شده — اگر یکی نبود، فایل حذف می‌شود
5. جلوگیری از **downgrade** (versionCode پایین‌تر رد می‌شود)
6. **هرگز نصب خودکار نیست.** پیش‌فرض: فقط اطلاع‌رسانی. دانلود+نصب فقط با تأیید صریح کاربر و از طریق `PackageInstaller` رسمی
7. کل جریان آپدیت در کنسول لاگ می‌شود تا قابل بازرسی باشد

### ⑤ هوش مصنوعی (ترکیبی، طبق انتخاب شما)
- **پیش‌فرض: کاملاً روی گوشی و آفلاین.** یک مدل multi-armed bandit (Thompson sampling) با ویژگی‌های: اپراتور/ASN، نوع شبکه (Wi-Fi/موبایل)، ساعت روز، تاریخچهٔ موفقیت هر (پروتکل × حالت اسکن × noize × endpoint)، پینگ، پایداری. هیچ داده‌ای از گوشی خارج نمی‌شود.
- **اختیاری و خاموش:** همگام‌سازی ابری از آمار جمعی. با توضیح شفاف اینکه چه چیزی ارسال می‌شود و سوییچ خاموش به‌صورت پیش‌فرض.

## ۴) دو نکتهٔ حقوقی که باید بدانید (کوتاه ولی مهم)

- **Aether لایسنس AGPL-3.0 دارد.** نتیجه این است که **اپ شما هم باید AGPL-3.0 باشد و سورس‌کدش منتشر شود.** این با انتشار روی GitHub (که برای آپدیت داخل‌برنامه هم لازم داریم) طبیعتاً حل می‌شود.
- **ByeDPI لایسنس MIT دارد** — کاملاً سازگار، بدون هیچ محدودیتی قابل ترکیب با AGPL.
- چون از کد patterniha چیزی کپی نمی‌شود (فقط ایده، و ایده کپی‌رایت ندارد)، GPL-3.0 آن الزامی ایجاد نمی‌کند؛ با این حال در About به آن اعتبار داده می‌شود.
- در فایل About باید به Aether، ByeDPI، SNI-Spoofing و Cloudflare quiche اعتبار داده شود. خودکار اضافه می‌کنم.
