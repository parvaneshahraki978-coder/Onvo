### شش آزمایش واقعی

همه **از داخل پروکسی** اجرا می‌شوند، نه شبکهٔ پیش‌فرض. این تفاوت بین
«هندشیک انجام شد» و «بسته‌ها واقعاً رد می‌شوند» است.

| آزمایش | روش |
|---|---|
| تغییر IP | `cdn-cgi/trace` قبل و بعد، مقایسهٔ واقعی |
| نشتی DNS | DNS-over-TCP از داخل پروکسی، بررسی ANCOUNT |
| نشتی IPv6 | تلاش عمدی مستقیم روی v6 — اگر جواب داد یعنی نشتی |
| توان عبوری | سه بار دانلود ۱۲۸KB و اندازه‌گیری |
| پایداری | مقایسهٔ نمونه‌ها؛ افت شدید یعنی ناپایدار |
| UDP | `UDP ASSOCIATE` روی SOCKS5 — خیلی شبکه‌ها TCP را رد می‌کنند و UDP را می‌بلعند |

اگر تونل وصل شود ولی ترافیک رد نکند، **شکست حساب می‌شود** و مسیر بعدی
امتحان می‌شود. این کل فلسفهٔ اندازه‌گیری به‌جای اعتماد است.

### هوش مصنوعی

`RouteBrain` یک **contextual multi-armed bandit** با نمونه‌گیری تامپسون
روی توزیع‌های بتا است. هر بازو یک استراتژی کامل است (پروتکل + عمق اسکن +
حالت desync)، و زمینه یک سطل درشت از شبکهٔ فعلی: اپراتور، وای‌فای یا
موبایل، و بازهٔ ۶ ساعته.

چرا تامپسون و نه «آخرین چیزی که کار کرد»: سانسور ثابت نیست. استراتژی‌ای
که امروز مرده ممکن است هفتهٔ بعد کار کند، پس نمونه‌گیر روی همهٔ بازوها
کمی احتمال نگه می‌دارد و خودش دوباره کشفشان می‌کند.

دانش قدیمی هم آرام **پوسیده** می‌شود تا یقین کهنه نمونه‌گیر را قفل نکند.

هیچ داده‌ای از گوشی خارج نمی‌شود. هیچ موقعیت مکانی، هیچ IP.

### جعل SNI بدون روت

بازسازی همان ایدهٔ SNI-Spoofing، ولی روی سوکت معمولی:

1. `setsockopt(IP_TTL, low)` تا طعمه قبل از سرور بمیرد
2. `vmsplice(SPLICE_F_GIFT)` صفحات ClientHello جعلی را به کرنل می‌دهد
3. همان صفحات در جا با دادهٔ واقعی بازنویسی می‌شوند
4. retransmit کرنل دادهٔ واقعی را با همان sequence می‌فرستد

DPI نام جعلی را ثبت و جریان را رد می‌کند؛ سرور اصلی طعمه را هرگز نمی‌بیند.

پنج استراتژی از سبک به سنگین: `SPLIT` → `DISORDER` → `FAKE` → `FAKE_MD5`
→ `AGGRESSIVE`. AI از سبک شروع می‌کند و فقط بعد از شکست بالا می‌رود، چون
desync سنگین هم تأخیر دارد هم قابل انگشت‌نگاری‌تر است.

## ساخت

```bash
bash tools/setup-toolchain.sh      # JDK 17 + Gradle + Android SDK
export JAVA_HOME=/home/user/.toolchain/jdk17
export ANDROID_HOME=/home/user/.toolchain/sdk
export GRADLE_USER_HOME=/home/user/.gradlehome
gradle :app:assembleDebug
```

باینری‌های native و نسخهٔ release در CI ساخته می‌شوند:
`.github/workflows/build.yml` هستهٔ Aether و ByeDPI را برای سه ABI
کراس‌کامپایل می‌کند، داخل `jniLibs` می‌گذارد و APK می‌سازد.

چهار secret: `KEYSTORE_B64`، `STORE_PASSWORD`، `KEY_ALIAS`، `KEY_PASSWORD`.

## تصمیم‌های فنی

**چرا هسته پروسه است نه JNI** — Aether یک باینری Rust مستقل است که کاملاً
با متغیر محیطی کنترل می‌شود و پیشرفتش را روی stdout می‌نویسد. پروسه یعنی
هرگز forkش نمی‌کنیم و هر انتشار جدید بدون تغییر جا می‌افتد.

**چرا `lib*.so`** — از اندروید ۱۰ فقط `nativeLibraryDir` اجازهٔ exec دارد،
و نصب‌کننده فقط فایل‌های `lib*.so` را استخراج می‌کند. به همین دلیل
`extractNativeLibs=true` هم لازم است.

**چرا SOCKS روی ۱۲۷.۰.۰.۱** — هستهٔ Aether احراز هویت ندارد. علاوه بر
بایند محلی، uid خود اپ از تونل خارج می‌شود وگرنه هسته می‌خواهد از تونلی
که خودش فراهم می‌کند عبور کند.

**چرا آیکون‌ها دستی‌اند** — `material-icons-extended` ده‌ها هزار وکتور
دارد و هم dex هم حافظهٔ build را می‌بلعد.
